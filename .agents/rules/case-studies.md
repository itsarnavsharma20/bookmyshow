# Case study rules

Applies to every folder that holds a system design case study.

- Each case study folder has a `README.md` that states the problem and links to its other notes.
- Follow the section order in the root [README.md](../../README.md): requirements, estimates, high-level design, data model and APIs, deep dives, trade-offs.
- Label numbers with units and assumptions. For example, `10M DAU, 2 requests per user per day`.
- Show the design with a diagram or a short text flow. Explain each component in one or two lines.
- When a design choice is made, write down the alternative and why it was not picked.
- Do not copy long text from external sources. Write the idea in your own words and link the source.

**Why:** The goal is to understand the reasoning, not to collect text.

**How to apply:** Before adding a new section, check that it fits the order above.
